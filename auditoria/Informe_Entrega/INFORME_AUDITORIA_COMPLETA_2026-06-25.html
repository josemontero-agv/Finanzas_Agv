🚨 Nueva Vulnerabilidad — Detectada en Junio 2026

🆕 NUEVA CRÍTICA Authentication Bypass via Service Credentials Fallback
📁 app/core/odoo.py:L147-150 🔒 OWASP: A07:2021 - Identification and Authentication Failures 📋 ISO 27001: A.9.4.2 - Secure log-on procedures ⚠️ CWE-287: Improper Authentication

Descripción: En el método authenticate_user(), cuando la conexión a Odoo falla por cualquier excepción (timeout, error de red, mantenimiento), el sistema utiliza un fallback que compara las credenciales del usuario con las credenciales de servicio del repositorio (ODOO_USER/ODOO_PASSWORD del .env). Esto permite que las credenciales del sistema actúen como "master password" para la aplicación.

⚠️ Código Vulnerable — app/core/odoo.py:L134-151
def authenticate_user(self, username: str, password: str) -> bool:
    try:
        common = xmlrpc.client.ServerProxy(f'{self.url}/xmlrpc/2/common')
        uid = common.authenticate(self.db, username, password, {})
        if uid:
            return True
        return False

    except Exception as exc:
        print(f"[ERROR] Error en autenticación contra Odoo: {exc}")
        # ⚠️ VULNERABLE: Fallback usando credenciales del SERVICIO
        if username == self.username and password == self.password:
            print("[OK] Autenticación exitosa usando credenciales del repositorio")
            return True   # ← cualquier usuario puede loguearse con creds del .env
        return False
✅ Corrección Recomendada
def authenticate_user(self, username: str, password: str) -> bool:
    try:
        common = xmlrpc.client.ServerProxy(f'{self.url}/xmlrpc/2/common')
        uid = common.authenticate(self.db, username, password, {})
        if uid:
            return True
        return False

    except Exception as exc:
        # ✅ Fallar seguro: si Odoo no está disponible, la auth FALLA
        # No usar credenciales de servicio como fallback
        import logging
        logger = logging.getLogger(__name__)
        logger.error("Error de conexión a Odoo durante autenticación: tipo=%s",
                     type(exc).__name__)  # no logear exc completo (info disclosure)
        return False  # ← fail-safe: sin autenticación si Odoo no disponible

Impacto: Si un atacante conoce las credenciales del .env.produccion (expuestas en git, logs o acceso al servidor), puede autenticarse en la aplicación web con ese usuario. La disponibilidad de Odoo se convierte en un factor de seguridad no intencional.

Vector de ataque: Ataque de mantenimiento programado — un atacante podría provocar indisponibilidad de Odoo (DoS al ERP) para activar el fallback y luego autenticarse.

🔴 Vulnerabilidades Críticas Persistentes (>30 días)

CRÍTICA 30+ DÍAS SIN RESOLVER 1. Token Falso (Dummy Token) — JWT Real No Implementado
📁 app/auth/routes.py:L96 🔒 OWASP: A07:2021 - Authentication Failures 📋 ISO 27001: A.9.4.2

El endpoint /api/v1/auth/login devuelve "dummy_token_12345" — un token estático, predecible y sin expiración. No hay implementación de JWT.

⚠️ Código Vulnerable (sin cambios desde mayo)
return jsonify({
    'success': True,
    'message': 'Login exitoso',
    'token': 'dummy_token_12345',  # ← CRÍTICO: token estático, predecible
    'user': username,
}), 200

Remediación pendiente: Instalar Flask-JWT-Extended y reemplazar con create_access_token(identity=username, additional_claims={...}). Esfuerzo estimado: 4 horas.

CRÍTICA 30+ DÍAS SIN RESOLVER 2. DEBUG=True en Configuración de Producción
📁 config.py:L188 + run.py:L66 🔒 OWASP: A05:2021 - Security Misconfiguration 📋 ISO 27001: A.12.1.1

Tanto ProductionConfig como el bloque de producción en run.py tienen DEBUG=True. En producción esto expone stacktraces completos, habilita el debugger interactivo de Werkzeug y puede permitir ejecución de código remoto.

⚠️ Código Vulnerable
# config.py:L185-189
class ProductionConfig(Config):
    DEBUG = True   # ← CRÍTICO

# run.py:L64-68
elif environment == 'production':
    app.run(host='0.0.0.0', port=5000, debug=True)  # ← CRÍTICO
✅ Corrección (15 minutos)
class ProductionConfig(Config):
    DEBUG = False   # ← cambiar

# run.py
elif environment == 'production':
    app.run(host='0.0.0.0', port=5000, debug=False)  # ← cambiar
CRÍTICA 30+ DÍAS SIN RESOLVER 3. Sin RBAC — Autorización de Un Solo Nivel
📁 app/auth/security.py 🔒 OWASP: A01:2021 - Broken Access Control 📋 ISO 27001: A.9.1.2 - Access to networks and network services

El decorador @require_login solo verifica session.get('logged_in'). No hay roles, permisos ni segregación de funciones. Un usuario cobrador tiene el mismo acceso que un administrador de tesorería.

⚠️ Código Vulnerable
# app/auth/security.py:L10-23 — único control de acceso
def require_login(view_func):
    if not session.get('logged_in'):
        return jsonify({'redirect': '/login'}), 401
    return view_func(*args, **kwargs)  # sin verificar rol/permiso

Remediación: Implementar roles en la sesión durante el login (consultar grupos de Odoo) y crear decoradores @require_role('treasury'), @require_role('collections'). Esfuerzo: 12 horas.

ALTA 30+ DÍAS SIN RESOLVER 4. Sin Rate Limiting — Fuerza Bruta en /login
📁 app/auth/routes.py + requirements.txt 🔒 OWASP: A07:2021 - Authentication Failures 📋 ISO 27001: A.9.4.3 - Password management system

Flask-Limiter no está instalado. El endpoint /api/v1/auth/login no tiene limitación de intentos. Un atacante puede intentar miles de combinaciones de contraseña por segundo.

✅ Corrección Rápida (1 hora)
pip install Flask-Limiter

# app/__init__.py
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address
limiter = Limiter(key_func=get_remote_address, default_limits=["200/day"])

# app/auth/routes.py
@auth_bp.route('/login', methods=['POST'])
@limiter.limit("10/minute;50/hour")  # max 10 intentos por minuto
def login(): ...
ALTA 30+ DÍAS SIN RESOLVER 5. Sin Protección CSRF en Endpoints POST
📁 app/auth/routes.py, app/emails/routes.py 🔒 OWASP: A01:2021 - Broken Access Control 📋 ISO 27001: A.14.2.5 - Secure system engineering principles

Los endpoints POST (/login, /logout, envío de correos) no tienen tokens CSRF. Un sitio malicioso puede hacer que el navegador de un usuario autenticado ejecute acciones no autorizadas.

Remediación: Instalar Flask-WTF y configurar CSRFProtect(app) o usar el header X-Requested-With como validación alternativa dado que la API es stateless REST. Esfuerzo: 2 horas.

MEDIA NUEVA 6. Cache Cross-Session — Datos de Usuario A servidos a Usuario B
📁 app/collections/routes.py:L30-32 🔒 OWASP: A01:2021 - Broken Access Control

Con CACHE_TYPE = 'simple' (caché en memoria de proceso), el caché es global y no está aislado por usuario. Dos usuarios con los mismos parámetros de query pueden compartir datos del caché.

⚠️ Código con riesgo
@collections_bp.route('/report/account12', methods=['GET'])
@require_login                                  # verifica sesión
@cache.cached(timeout=300, query_string=True)   # caché global por params
def report_account12():
    # Si usuario A y usuario B tienen los mismos parámetros de filtro,
    # el cache puede devolver datos del otro usuario (con simple cache)
✅ Corrección — Cache por usuario
@collections_bp.route('/report/account12', methods=['GET'])
@require_login
def report_account12():
    from app.auth.security import get_authenticated_user_email
    user_email = get_authenticated_user_email()
    # Cache key incluye el usuario
    cache_key = f"report12_{user_email}_{request.query_string.decode()}"
    cached = cache.get(cache_key)
    if cached:
        return jsonify(cached)
    # ... procesar datos
    cache.set(cache_key, result, timeout=300)
    return jsonify(result)
MEDIA NUEVA 7. DoS Potencial — limit=0 Sin Restricción Máxima
📁 app/collections/routes.py:L54 · app/exports/routes.py:L52 🔒 OWASP: A04:2021 - Insecure Design
⚠️ Sin límite máximo
# collections/routes.py:L54 y exports/routes.py:L52
limit = request.args.get('limit', type=int, default=0)
# limit=0 → Odoo search_read sin límite → puede traer millones de registros
# Un usuario autenticado puede inducir carga masiva al servidor
✅ Corrección
MAX_LIMIT = 10_000  # definir en config.py
limit_raw = request.args.get('limit', type=int, default=0)
limit = min(limit_raw, MAX_LIMIT) if limit_raw > 0 else MAX_LIMIT

📁 app/auth/routes.py:L113-115 🔒 OWASP: A05:2021 - Security Misconfiguration
⚠️ Expone detalles de infraestructura
except Exception as e:
